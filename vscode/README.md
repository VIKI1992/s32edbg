# S32E Debug

Debug NXP S32E27x boards over a SEGGER J-Link from its own Activity Bar container — no Run-and-Debug tab involved. Backed by the `s32edbg` CLI in the parent repository.

Features: persistent probe session, per-core run control for 4× Cortex-R52 + 3× Cortex-M33, source- and instruction-level stepping, gutter breakpoints on a focused core, watchpoints, call stack + raw stack, a Variables view (frame-linked locals, filterable globals, persisted watch paths, scalar editing, live refresh while running), disassembly view, RAM ELF loading, catch-at-first-instruction, memory viewer, PC profiling, and pre-connect board diagnostics.

Interactive latency (2026-08-11): source-line steps use comparator range-stepping (straight-line stretches run at silicon speed; only real control flow is single-stepped), breakpoint hits are **pushed** by the backend within ~50 ms instead of being discovered by the status poll, and each stop's registers/stack/variables refresh shares one hardware read through per-stop caches. The S32E output channel prints every request's backend cost as `<ms>ms/<ops>op` — one `op` is one USB round trip — so a slow operation names its own cause.

Halted rows in the Cores view carry inline step buttons (step-into and step-over by source line, step by instruction) beside continue — on a non-focused core they focus it first, then step. Per-tab refresh control: Cores, Variables, Call Stack, Registers, Memory, Breakpoints and Watchpoints each start with an **Auto-refresh checkbox** row.

The Breakpoints/Watchpoints checkboxes gate a **hardware-comparator verification** sweep (`s32e.comparators.verifyMs`, default 5 s, plus one pass per stop): each row gains `✓ hw` when its comparator really is armed at its address, a yellow `⚠ hw:` marker when the hardware disagrees (e.g. a target-side reset wiped the slot), and enabled comparators nobody claims appear as orphan rows with a right-click **Clear Hardware Comparator** action. An unreadable comparator bank (OS lock / reset hold) reads as `hw: unreadable` and never demotes your list.

**The Scope** (chart icon on any Variables row with a memory address, or `S32E: New Plot Panel`): a multi-signal oscilloscope fed by backend **streaming** (`var sample` — batched reads pushed as events; measured **~755 samples/s** for one signal on the bench, split evenly across up to 6 signals). Signals are managed in the panel's sidebar — color chip, live value, show/hide, ✕ remove — and by the chart icon on further rows. The sidebar box is a **live picker**: typing searches every plottable global and static in the ELF (backend `var names` — symbol-index only, no target reads; statics are qualified `file.c::name`, function statics `file.c::func::name`), ↑/↓ + Enter or a click adds the variable; Enter on free text still resolves it as a watch path (`cfg.limits[1].max`), so struct members and array elements stay reachable. **Zoom** is axis-selectable: the `zoom X | Y | XY` toggle picks which axis the mouse wheel scales (X changes the time span beyond the window presets; Y hands the hovered lane — or every overlay signal — a manual range, e.g. out to a full 32-bit sweep), double-click or **Fit** returns to autoscale + live follow, and Alt+drag pans back through history (the view detaches from live and re-attaches when dragged back to now). Layout toggles between **lanes** (one strip per signal) and **overlay**; overlay is per-signal normalized by default (an 8-bit and a 16-bit counter wrap look equal), while **Match Y** switches every signal onto one shared absolute scale — equal values at equal height — in either layout. Two **time cursors** (click for A, again for B, drag to adjust, Esc clears) read out t, per-signal values and Δt/Δvalue; per-pixel min/max decimation keeps kHz traces honest; CSV exports long-format `timestamp_ms,signal,value`. One total rate knob (`s32e.plot.sampleHz`, default 100, up to 1000) is shared by all signals; the achieved rate is always displayed (wall-clock arrival count — it keeps updating with cursors placed and decays to 0 within 2 s of a stall). Streaming reads addresses, not handles, so run/stop cycles never interrupt the trace, and a step issued mid-stream waits at most one ~50 ms batch. Checked, the tab refreshes on its usual trigger (the status poll for Cores, the on-stop fetch for the rest; Memory — off by default — re-reads its open regions at every stop). Unchecked, the tab causes no probe traffic: it keeps its last values with a `paused` hint, and its refresh button still does a one-shot. The choice persists per workspace. A yellow **gutter arrow** marks the current PC line in the source editor and the disassembly view — both at once when both are open — moving with every step and clearing on resume.

## Requirements

- Windows, 64-bit Python ≥ 3.11 with the backend installed: `pip install -e <repo-root>[ide]`
- A SEGGER J-Link install (auto-discovered, or set `s32e.jlinkDir`)

## Getting started

1. Set `s32e.pythonPath` if `python` on PATH is not the interpreter with s32edbg.
2. Open the S32E Debug container in the Activity Bar → **Connect**.
3. Pick your ELF (status bar) → set breakpoints → debug.

Full documentation: see the repository README ("IDE integration" section).
